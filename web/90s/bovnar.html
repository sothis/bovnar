What is Bovnar?

"Hand a .bvnr file to anyone. They have everything they need."

Serialisation formats make a quiet trade-off: either they are easy for humans to read, or they carry precise machine-readable semantics — rarely both. JSON tells you that 9.81 is a number. It does not tell you whether it is meters per second, volts, or a dimensionless ratio. Protobuf tells you the field type, but requires a .proto schema file and a compiler just to decode the payload.

Bovnar makes a different choice. Every value in a .bvnr document is self-describing: the type family, bit-width, numeric base, and physical unit all travel with the value, in the same byte stream, without any external schema. 

# A self-describing Bovnar document
.config = {
    .host    = "api.example.com";
    .port    = <uint:16> 443;
    .timeout = <float:64,s> 2.5;
    .cache   = <uint:64,Mi~B> 16;
};
.velocity     = <float:64,m/s>   9.81;
.acceleration = <float:64,m/s²>  9.81;
.force        = <float:64,k~g·m/s²> 9.81;  # Newton
.matrix       = <float:64> [1.0, 0.0, 0.0]
                            /[0.0, 0.866, -0.5]
                            /[0.0, 0.5,   0.866];

The format is UTF-8 throughout, readable and writable by hand, with an optional binary embedding mechanism (octet streams) for raw payloads — no Base64 overhead.

Key Features
Strong, Optional Typing
Six type families: uint, sint, float, float_fix, float_dec, utf8. Explicit bit-width from 8 to 32768 bits. Numeric base: binary, octal, hex, base-64, base-85. Omit annotations and get sensible defaults. Add them and get compile-time validation.
First-Class Physical Units
SI base and derived units, compound units (m/s², k~g·m/s²), and IEC binary prefixes (Ki~B, Gi~B) inline — no schema needed. Up to 8 components per compound unit with Unicode exponents.
Native Binary Embedding
Octet streams embed raw binary data without Base64 overhead. The writer API handles framing automatically. UTF-8 validation is suspended during binary regions.
Multi-Dimensional Arrays
Rows separated by /: [1,2,3]/[4,5,6] is a native 2D matrix. Per-element or whole-array type annotations. Sparse arrays via null elements.
Streaming SAX-Style Reader
Incremental parsing from memory, file descriptor, or socket. Dual-callback design: on_unverified and on_verified. Zero allocations on the hot path. Suitable for embedded and high-throughput systems.
Fixed-Point & Decimal Float
float_fix (Q~format, e.g. <float_fix:32,q16>) for embedded DSP. float_dec (IEEE 754-2008 decimal) for financial and metrological contexts where 0.1 must be exactly representable.
Error Recovery Mode
Optional continue_on_error mode skips broken assignments and resumes parsing — designed for log streams and unreliable transports. Error count tracked via bvnr_reader_get_recovery_count().
Python Bindings
Pure ctypes — no compiled extension required. High-level loads() / dumps() dict-like API and a low-level event-driven streaming API. Unit helpers: unit_convert_factor(), units_compatible().
Extensively Tested
Unit tests, socket-pair round-trip tests, fuzz harnesses (reader, writer, DOM, utils), and a benchmark binary. CI-ready. Fuzzing seeds included.
Configurable Limits
All size limits live in bvnr_read_flags_t: identifier length, string length, array items, nesting depth, file size. Defaults are permissive; production deployments set explicit caps.
Syntax Highlighting
Ready-made grammars for VS Code and Geany. Install scripts included. TextMate grammar format for easy porting.
DOM API
Optional in-memory DOM builder on top of the streaming reader. Navigate and query the document tree without writing a custom event handler. C API: bovnar_dom.h.
Syntax at a Glance

Every Bovnar document is a sequence of assignments. The grammar is minimal:

assignment ::= '.' identifier '=' [ type-annotation ] value ';' identifier ::= (letter | '_' | utf8-high) (letter | digit | '+' | '-' | '_' | utf8-high)* annotation ::= '<' type-family [ ':' param (',' param)* ] '>' param ::= width | '_' base | unit-expr | 'q' integer comment ::= '#' .* newline

The three things to remember:

Keys start with . .myKey = value; The dot is a hard syntactic marker, not decoration.
Annotation between = and value .x = <uint:32> 42; Placing it on the key is a hard error.
Semicolon terminates every assignment .x = 1; Inside structs too: {.x = 1; .y = 2;}

    .burst_size = <uint:16>        8;
    .adc_bits   = <uint:8>         12;
};

    .offset = <float_fix:32,q8,°C>   -0.5;
    .gain   = <float_fix:32,q16>       1.002;

Type System

The type annotation is enclosed in angle brackets and placed between = and the value. Three parameter classes can appear in any order:

Type Families

uintUnsigned integer
sintSigned integer
floatIEEE 754 binary float
float_fixQ~format fixed-point
float_decIEEE 754-2008 decimal
utf8UTF-8 string

Width Examples

uint:80 .. 255
uint:1212-bit ADC sample
float:16half-precision
float:32single-precision
float:64double-precision (default)
float:128quad-precision
# Width: any positive integer for uint/sint
.adc    = <uint:12> 2048;    # 12-bit ADC
.status = <uint:4>  0b1101;  # nybble, any positive width is valid

# Base: _2 _8 _10 _16 _36 _62 _64 _85 (non-decimal must be QUOTED)
.mac   = <uint:48,_16>  "AABBCCDDEEFF";
.perms = <uint:16,_8>   "755";
.neg   = <sint:32,_16>  "-7FFFFFFF";   # minus inside the string

# Q~format fixed-point
.adc_v = <float_fix:16,q8>   3.14;   # 16-bit, 8 fractional bits
.pid   = <float_fix:32,q16>  -1.5;   # Q must be < width

# Decimal float — exact 0.1, useful for finance / metrology
.price   = <float_dec:32>   12.99;
.voltage = <float_dec:64>   101325.0;
Default type synthesis: bare 42 → uint:64, bare -7 → sint:64, bare 3.14 → float:64. The parser always produces a fully-resolved type even without an annotation.
Gotcha: Non-decimal literals must be quoted strings. .x = <uint:8,_16> FF; → error_type_value_mismatch — FF is parsed as a symbol. Correct: .x = <uint:8,_16> "FF";
Physical Units — First Class

The unit is a parameter inside the angle brackets, after width and base. SI prefixes use a mandatory tilde: k~m, M~Hz, µ~s. IEC binary prefixes follow the same pattern: Ki~B, Gi~B. 

# Simple units
.timeout  = <float:64,s>    2.5;      # seconds
.distance = <uint:64,m>    384400000; # meters
.voltage  = <float:32,V>    3.3;
.temp     = <float:32,°C>   23.5;     # UTF-8 units fine

# SI prefixes (tilde is mandatory)
.k_ohm = <float:32,k-Ω>   4.7;     # kilo-ohm
.micro = <float:32,µ~s>   50.0;    # microsecond
.giga  = <float:64,G~Hz>  2.4;     # gigahertz

# IEC binary prefixes
.ram  = <uint:64,Gi~B>  8;
.disk = <uint:64,Ti~B>  2;

# Compound units: * or · for multiply, / for divide (one-way switch)
.velocity     = <float:64,m/s>         9.81;
.acceleration = <float:64,m/s²>        9.81;
.force        = <float:64,k~g·m/s²>    9.81;   # Newton
.energy       = <float:64,k~g·m²/s²>   1000;  # Joule
.pressure     = <float:64,k~g/(m·s²)>  101325; # Pascal

# Exponents: Unicode superscripts OR ASCII caret — both valid
.area1 = <float:64,m²>   100.0;
.area2 = <float:64,m^2>  100.0;   # identical
.inv   = <float:64,s⁻¹>  50.0;
.inv2  = <float:64,s^-1> 50.0;   # identical

# Inline suffix — shorthand without full annotation (scalar context only)
.speed = 9.81 m/s;    # → float:64, unit = m/s
.mass  = 70.0 k~g;

# Explicitly dimensionless
.ratio = <float:64,no_unit> 1.4142;
Max 8 unit components. The / separator is a one-way switch — once written, all subsequent components are in the denominator. Use negative exponents (s⁻²) to put a component back in the numerator.
Bovnar does not convert units. The annotation is parsed, validated, and delivered to your application. Conversion and dimensional checking are intentionally left to the application layer (Python helpers: unit_convert_factor(), units_compatible()).
Arrays & Structs

Arrays

# 1D
.primes = [2, 3, 5, 7, 11];

# 2D — rows separated by /
.R = <float:64> [1.0, 0.0, 0.0]
               /[0.0, 0.866, -0.5]
               /[0.0, 0.5,  0.866];

# Per-element annotations
.mix = [<uint:8> 255,
        <sint:8> -128,
        <float:64> 3.14];

# Whole-array annotation
.temps = <float:32,°C> [23.5, 24.1, 22.8];

# Sparse — leading/trailing commas = null
.sparse = [, 1, , 2, ];
# → null, 1, null, 2, null

Structs

# Nested struct
.db = {
  .host = "db1.internal";
  .port = <uint:16> 5432;
  .tls  = {
    .cert = "/etc/ssl/db.pem";
  };
};

# Array of structs
.users = [
  {.id = <uint:32> 1;
   .name = "Alice";
   .role = admin;},
  {.id = <uint:32> 2;
   .name = "Bob";
   .role = user;}
];

# Empty struct is valid
.placeholder = {};

Get It

C99 Reference Library

Single-translation-unit design. Drop the sources into your project or build with CMake. Requires no external dependencies for the core. GMP is optional for extended integer support.

git clone https://github.com/yourorg/bovnar
mkdir build && cd build
cmake .. && make
./run_tests.sh

C99 · MIT license · Linux / POSIX · fuzz-tested

Python Bindings

Pure ctypes — no compiled extension. Install the shared library, then:

import bovnar

doc = bovnar.loads("""
.speed = <float:64,m/s> 9.81;
.host  = "localhost";
.port  = <uint:16> 8080;
""")

print(doc["speed"])  # 9.81
print(doc["port"])   # 8080

out = bovnar.dumps({"voltage": 3.3})
print(out)  # .voltage = 3.3;
