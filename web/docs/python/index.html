Pure-ctypes Python bindings for the Bovnar (BVNR) typed serialisation library (library 2.0.2, format spec 1.2).

No compiled extension module is needed — the bindings load libbvnr.so through the standard ctypes.CDLL machinery the first time something needs the C library; import bovnar itself never loads it.

Requirement Notes
Python ≥ 3.10 dataclasses, enum.IntEnum, union-type annotations (X \| Y)
libbvnr.so Runtime only, and bundled inside the wheel — see Library discovery below
numpy ≥ 1.24 Optional — only for the NumPy bridge (pip install bovnar[numpy])
pint ≥ 0.22 Optional — only for the pint bridge (pip install bovnar[pint])

2. Installation

# From PyPI. The wheels bundle libbvnr, so there is nothing to build and no
# system dependency to install.
pip install bovnar

Optional extras pull in the dependencies for the bridges:

pip install "bovnar[numpy]"   # NumPy bridge
pip install "bovnar[pint]"    # pint bridge
pip install "bovnar[all]"     # both numpy and pint

From a source checkout instead. pyproject.toml lives at the repository root, not under python/ — the pure-Python package there is mapped into the wheel by [tool.scikit-build] wheel.packages, so the editable install runs from the root:

cmake -B build . && cmake --build build      # produces build/libbvnr.so
export LIBBOVNAR_PATH="$PWD/build/libbvnr.so"

pip install -e ".[dev]"                      # from the repository root

3. Library discovery

The bindings search for libbvnr.so in this order:

  1. LIBBOVNAR_PATH — absolute path to the .so file, e.g. bash export LIBBOVNAR_PATH=/opt/bovnar/lib/libbvnr.so
  2. LIBBOVNAR_DIR — directory that contains the .so, e.g. bash export LIBBOVNAR_DIR=/opt/bovnar/lib
  3. Bundled in the package — the library sitting next to _ffi.py inside the installed bovnar package. This is the normal path after pip install bovnar: CMake installs libbvnr.* into the package directory when the wheel is built, so an installed wheel resolves here and needs no environment variable at all.
  4. ctypes.util.find_library('bvnr') — standard ldconfig / LD_LIBRARY_PATH search.
  5. In-tree build paths — ../../build/, ../../build/release/, ../../, . (resolved relative to the _ffi.py file; useful when building Bovnar alongside the bindings from a mono-repo).

The search runs on first use, not at import: import bovnar succeeds without the library, and the first call that needs it (loads, Reader(), parse_unit, …) raises BovnarLibraryNotFound if none of the candidates loads. The message lists every candidate tried, in order, with why each one failed (not found, or the loader's error).

4. Quick-start

4.1 High-level API (loads / dumps)

import bovnar

# Serialise a Python dict to BVNR bytes
data = {
    "sensor_id": 42,
    "temperature": -3.7,
    "label": "outdoor",
    "active": True,
    "payload": None,
}
bvnr_bytes = bovnar.dumps(data)

# Deserialise back to a Python dict
recovered = bovnar.loads(bvnr_bytes)
assert recovered["sensor_id"] == 42

nan, inf and ninf come back as float, under an integer type as well (<uint:8> nan, spec §6.4), as dom_parse() gives them.

loads and load take the read options of Reader.read_mem as keywords (§11.2): bovnar.loads(data, max_file_size=1 << 20, strict_version=True, max_string_length=4096) reads untrusted input under tighter limits than the defaults.

loads accepts an optional typed flag that wraps typed values in Quantity objects instead of decoding them to native Python scalars. This preserves the original text representation, exact type width, numeral base, and physical unit for lossless round-trips:

bvnr = b".pressure = <float:32,Pa> 101325.0;"
doc  = bovnar.loads(bvnr, typed=True)
q    = doc["pressure"]     # Quantity('101325.0', FLOAT [Pa])
print(q.raw)               # '101325.0'
print(q.unit_str)        # 'Pa'

# dumps() accepts Quantity values — annotation and raw text are re-emitted as-is
out = bovnar.dumps(doc)
assert bovnar.loads(out, typed=True) == doc

Two Quantity objects are equal (and hash alike) when their literal, unit and effective type agree: a width of 0 is 64 and a radix of 0 is 10, as the C library reads them, so <float:64,_10> 5.7, <float:0> 5.7 and a bare 5.7 are one value. (The base field of float_fix and datetime is Q and the epoch index, and is compared as stored.) dumps() writes the canonical annotation, which is why the assertion above holds for a document that spelled the defaults out. It also holds for a quoted numeric literal (<float:64> "5.7") and for a typed null (<float:64> ;, [<uint:32>, <sint:64>]): dumps() writes the annotation either one needs to read back as itself.

dumps() starts with a 4 MiB write buffer and doubles it automatically on overflow, up to 256 MiB. The cap keyword argument that existed in earlier versions is no longer accepted.

bovnar.load(f) and bovnar.dump(obj, f) are the two for a socket or a binary file object, with the same options and the same result: load pulls the bytes as the parse needs them and dump pushes the output through the writer's 64 KiB buffer, so neither holds the whole document (Reader.read_stream, Writer.to_stream). The one difference is a failure on the way out: what dump pushed before a refused value has already reached the stream.

import io

buf = io.BytesIO()
bovnar.dump({"sensor_id": 42, "label": "outdoor"}, buf)
buf.getvalue() == bovnar.dumps({"sensor_id": 42, "label": "outdoor"})   # → True
bovnar.load(io.BytesIO(buf.getvalue()))["label"]                        # → 'outdoor'

dumps() takes None, bool, int of any size, float, str, Decimal, a terminating Fraction, bytes / bytearray / memoryview (written as an octet stream — which is what loads() returns as bytes), Quantity, a dict with str keys, and a list / tuple of those. NumPy scalars are taken as the Python numbers they are.

dumps() writes what loads() reads — the streaming tier, not the document tier. loads() checks the grammar and each value's own type, unit and range and stops there; dumps() is its inverse and stops in the same place, so dumps(loads(x)) works for every x that loads() accepts. Three shapes are therefore written without complaint and then refused by the document tier (dom_parse, bovnar validate), where an array is homogeneous and rectangular:

Python value Written as Document tier says
[1, "a"], [True, 1] — a list mixing kinds [1, "a"] array_element_type_mismatch
[[1], [2, 3]] — a ragged list of lists [[1], [2, 3]] array_row_size_mismatch
[{"a": 1}, {"b": 2}] — dicts that do not share their keys [{.a = <uint:64> 1;}, {.b = <uint:64> 2;}] struct_shape_mismatch

A list mixing int and float, or holding None beside values, is fine at both tiers. If the output has to pass bovnar validate, run it through dom_parse() before shipping it.

What dumps() does refuse, with BovnarArgumentError, is what neither tier reads: a list whose elements carry different units, an integer wider than 64 bits in a list that cannot take the width annotation it needs ([2**70, 1.5]), a Decimal past the range of float_dec:64, a key that is not a str, a key that is not a Bovnar identifier (spec §4.2: "a b", "1a", "a.b", ""), a key longer than 255 bytes in UTF-8 (the reader's default max_identifier_length, which loads(), dom_parse() and bovnar validate read with), and a string — or a key — holding a control character other than TAB, LF, VT, FF and CR ("\x00", "\x7f") or a lone surrogate. The message names the key.

4.2 SAX-style streaming reader

The verified callback receives exactly two positional arguments: the event code and the data payload. There is no userdata/context argument — capture external state via closure instead.

from bovnar.reader import Reader
from bovnar import Event

def on_event(ev, data):
    if ev == Event.ASSIGNMENT_START:
        print("key:", data.raw_str())
    elif ev == Event.DATA:
        print("value bytes:", data.raw_bytes())
    return True   # returning False stops parsing (raises BovnarParseError)

with Reader() as r:
    r.read_mem(bvnr_bytes, on_verified=on_event)

The BvnrData payload passed to a callback exposes:

Method Returns Description
data.raw_str(encoding='utf-8') str The token bytes decoded as text
data.raw_bytes() bytes The raw token bytes
data.converted_str() str \| None Exact want_unit conversion result as a positional string, or None if no conversion / it does not terminate in its base
data.converted_in_base(base) str \| None The exact conversion re-rendered in base
data.converted_rational() tuple[int, int] \| None The exact conversion as (numerator, denominator)
data.frac_str() str \| None Verbatim ISO sub-second digits of a datetime literal (spec 1.1), or None
data.unit_source_str() str \| None The unit exactly as the document spelled it (library 2.0), or None when the value carries no unit

It also carries the converted (bool) and value_type / value_unit fields directly.

A payload may outlive its callback. The BvnrData a callback (or a want_unit hook) receives is a copy the binding owns, not a view of the reader's memory: the token bytes, the sub-second digits, the unit spelling and the exact conversion (conv.num/conv.den) are all copied out before the callback runs. A callback can keep the object, and every method in the table above returns the same answer after the callback has returned and after the reader is closed.

4.4 DOM (random-access) API

import bovnar

dom_bytes = b"""
.sensor_id = <uint:64> 42;
.config = {
    .host = "localhost";
    .port = <uint:16> 8080;
};
.values = [1.5, 2.5, 4.0];
"""
doc = bovnar.dom_parse(dom_bytes)

# Top-level key lookup
node = doc["sensor_id"]
print(node.as_i64())        # → 42
print(node.value_type)      # ValueTypeSpec(family=UINT, width=64, base=0)

# Struct traversal
cfg = doc["config"]
host = cfg["host"].as_str()
host                        # → "localhost"

# Array access
arr = doc["values"]
for i in range(len(arr)):
    print(arr[i].as_float())    # 1.5, 2.5, 4.0

# Convert entire document to a plain Python dict (drops type/unit info)
d = doc.to_dict()
d["config"]["port"]         # → 8080

4.6 Streaming / framing (bovnar.stream)

Bindings for the streaming layer (see Streaming, Framing & Multiplexing for the full treatment):

from bovnar import stream

# Multi-document record framing
blob = stream.dump_documents([{"id": 1}, {"id": 2}])   # list[dict] -> bytes
docs = stream.load_documents(blob)                      # bytes -> list[dict]
docs = stream.load_documents(blob, continue_past_failed=True)  # bad docs -> None
docs = stream.load_documents(blob, continue_past_failed=True,
                             return_errors=True)   # bad docs -> their error

# Octet multiplexing: (channel, payload) of any size, interleaved & reassembled
multiplexed = stream.mux_dump([(1, b"hello"), (42, b"world")])
messages    = stream.mux_load(multiplexed)             # [(1, b"hello"), (42, b"world")]

# Document-in-document
outer = stream.embed_document(bovnar.dumps({"v": 1}), key="payload")
inner = stream.parse_embedded(bovnar.loads(outer)["payload"])   # {"v": 1}

With return_errors=True a document that failed is the BovnarParseError it failed with instead of None: its code is the document's error code and its index the document's position in the stream (and in the list). The frame reader reports the code alone, so the error carries no position. FrameFeed(parse=True, continue_past_failed=True, return_errors=True) (§4.7) hands out the same.

bad = stream.frame_documents([b".a = 1;", b".a = @;", b".b = 2;"])
docs = stream.load_documents(bad, continue_past_failed=True,
                             return_errors=True)
docs[0]                              # → {'a': 1}
docs[1].code.name                    # → 'UNEXPECTED_INPUT_BYTE'
docs[1].index                        # → 1

parse_embedded raises BovnarParseError carrying the inner document's own error code and position. mux_dump takes channels in the unsigned 64-bit range and raises BovnarArgumentError for anything outside it. The key of mux_dump, MuxWriter and embed_document is held to the rule dumps() holds a key to (§4.1), with the same BovnarArgumentError; the key filter of mux_load and DemuxFeed may not hold a NUL.

mux_dump(..., preamble={...}) writes a dict of ordinary values before the stream opens — what the stream is, read by a consumer before its first message (§4.7). load_documents and mux_load also take a socket or a binary file object in place of bytes and read it to its end, parsing as they pull; frame_documents, dump_documents, mux_dump and embed_document take a file= to write to instead of returning bytes. The results are those of the in-memory calls.

load_documents, mux_load and parse_embedded take the read options of Reader.read_mem (bovnar.READ_OPTIONS, §11.2) as keywords, and read under them: load_documents each document, with max_file_size capping one document and max_document_size one frame; mux_load the document around the stream; parse_embedded the embedded document, as a document of its own, with max_file_size capping its bytes. All three read with no total cap by default. max_document_size and max_message are held to the rule of the read limits: an int from 0 to 2**64 − 1, or BovnarArgumentError. Bytes handed to these functions — a payload, a document, the input — are any bytes-like object (an mmap is read whole, not from its position) or a str, taken as UTF-8; anything else is a BovnarArgumentError.

To write a mux stream, or an embedded document, inside a document of any shape — values after it, more than one stream — use the Writer (§12.9): mux_begin(key), mux_send(channel, payload), mux_end() and embed_document(key, doc). mux_dump and MuxWriter end the document with their stream.

4.7 Live streams: feeding in pieces

The functions above take the whole input, or read a stream to its end. For input that arrives when it arrives — a non-blocking socket, an event loop, a queue — three objects in bovnar.stream each keep one C reader for the whole stream and are handed bytes in pieces of any size, cut anywhere:

Object Fed Hands out
DocumentFeed one document DocumentEvent(event, data) per verified event, as a Reader callback receives it; with values=True, Value(key, value) per top-level value once it is complete as well (events=False for the values alone)
DemuxFeed a document carrying a mux stream Message(channel, payload) per message; with values=True the values before and after the stream, in document order; with events=True the document's events
FrameFeed a BVF1 frame stream each document's bytes; with parse=True each document parsed, as load_documents parses it

All three take the read options of Reader.read_mem (bovnar.READ_OPTIONS, §11.2): max_file_size, the text, array, length and nesting caps, continue_on_error, strict_version, text_only and the rest. Besides those: DocumentFeed takes typed, want_unit, on_error, on_unverified and mirror, and has the recovery_count, skipped_bytes and declared_version of its reader (§11.6); DemuxFeed(key=None, max_message=0, typed=False, view=False), whose recovery_count, skipped_bytes and declared_version are those of its reader, as on DocumentFeed; FrameFeed(parse=False, typed=False, continue_past_failed=False, max_document_size=0, view=False, return_errors=False), where typed, continue_past_failed, return_errors (§4.6) and the read options need parse=True (each parsed document is read under them, max_file_size capping one document) and view needs parse=False (otherwise BovnarArgumentError). DemuxFeed's key=None demultiplexes every octet stream of the document, as mux_load does, while mux_dump and MuxWriter write under key="mux": a document with any other octet stream — a bytes value in the preamble, say — needs key= on the reader.

feed(data) returns the object itself, which iterates over what those bytes completed, and finish() says the input is over. Running out of input is never an error; finish() raises BovnarParseError for a document or frame cut off part-way. Every other error carries the code the batch function gives — loads, mux_load, load_documents (a failed document's own code, a bad magic UNEXPECTED_INPUT_BYTE, a frame over max_document_size VALUE_OUT_OF_RANGE, a stream cut inside a frame GOT_INCOMPLETE_BVNR_STREAM). DocumentFeed raises from the feed() whose bytes hit the error, with the reader's position, and drops what that feed had completed; DemuxFeed and FrameFeed raise from the iteration that reaches it, after the items before it (an exception from one of your own callbacks comes out of the call it was raised in). finish() raises at once. Each is a context manager that frees its C object.

A stream that starts with metadata hands it over before the first message:

from bovnar import stream

doc = stream.mux_dump([(1, b"frame-1"), (2, b"audio"), (1, b"frame-2")],
                      key="media", preamble={"meta": {"codec": "av1"}})
doc += b".end = true;\n"

items = []
with stream.DemuxFeed(key="media", values=True) as dm:
    for at in range(0, len(doc), 16):          # as a socket might deliver it
        items.extend(dm.feed(doc[at:at + 16]))
    items.extend(dm.finish())

items[0]                             # → ('meta', {'codec': 'av1'})
items[1]                             # → (1, b'frame-1')
items[-1]                            # → ('end', True)
isinstance(items[1], stream.Message) # → True

Message, Value and DocumentEvent are named tuples, so channel, payload = item works, and isinstance tells them apart. The key scope, max_message (0 selects BVNR_MUX_DEFAULT_MAX), the 4096-channel limit and the error codes are those of mux_load.

A document that never ends is read a value at a time; a value handed over is not kept, so memory stays flat:

values = stream.DocumentFeed(events=False, values=True)
first  = list(values.feed(b'.reading = 1; .read'))
second = list(values.feed(b'ing = 2; .x = [1, 2];'))
last   = list(values.finish())
first                                # → [('reading', 1)]
second                               # → [('reading', 2)]
last                                 # → [('x', [1, 2])]

A scalar, a struct or an octet stream is complete at its end; an array at the next key or the end of the document, because a further /[…] row would extend it. An octet stream in a DocumentFeed is gathered whole before it is handed over, so an endless one belongs in a DemuxFeed or is read by its events. The text of a fed document is capped as Reader's is, at 2 147 483 647 bytes (TEXT_DATA_TOO_LONG, doc/10 §1), and an array at as many items: pass max_text_bytes=stream.BVNR_NO_LIMIT (and max_array_items) for a document that does not end. DemuxFeed and a parsing FrameFeed take both as well. DocumentFeed takes no on_verified, which the feed's items stand in for; with values=True, typed=True gives Quantity values as loads(typed=True) does (typed without values, or neither events nor values, is refused). on_unverified(event, data) sees the raw lexer events of the bytes each feed() hands over, inside that call: the events Reader.read_mem(on_unverified=...) delivers for the whole document, wherever it was cut. mirror receives the bytes the reader consumes, each piece once the reader has parsed it (§11.2). A want_unit, on_error or on_unverified callback runs inside the C call, so it may not close the feed or feed it again (BovnarArgumentError); an exception it raises, or one the mirror raises, comes out of the feed() or finish() it was raised in. One feed reads one document: make a new one for the next.

raw = []
mirrored = bytearray()
feed = stream.DocumentFeed(events=False, values=True, mirror=mirrored,
                           on_unverified=lambda ev, d: raw.append(ev.name))
got = list(feed.feed(b'.a = ')) + list(feed.feed(b'1;')) + list(feed.finish())
got                                  # → [('a', 1)]
bytes(mirrored)                      # → b'.a = 1;'
raw[:2]                              # → ['STREAM_START', 'ASSIGNMENT_START']

frames = stream.FrameFeed(parse=True)
blob = stream.dump_documents([{"id": 1}, {"id": 2}])
docs = list(frames.feed(blob[:30])) + list(frames.feed(blob[30:]))
frames.finish()
docs                                 # → [{'id': 1}, {'id': 2}]
frames.count                         # → 2

The fed bytes. DemuxFeed and the unparsed FrameFeed are drained with bvnr_demux_next / bvnr_frame_reader_next, which point into the fed bytes: those are kept until the iteration has run to its end, and feeding again before then raises BovnarArgumentError. A bytearray is copied when fed, so the usual recv_into loop may refill it at once.

Memoryview payloads. By default a payload is bytes. With view=True (DemuxFeed, unparsed FrameFeed) it is a read-only memoryview of the reader's own memory instead — the fed bytes for a message that lay whole in one chunk, a reassembly buffer otherwise — which saves a copy per message and is valid only until the next call on the feed: the next item, feed(), finish() or close(). The feed releases the view then, so using it later raises ValueError rather than reading memory that has been reused. Copy what must be kept with bytes(view). A buffer made from the view — memoryview(view), a slice of it, numpy.frombuffer(view), a held export — is not released with it, so while one is alive the next call raises BovnarArgumentError and leaves the stream as it was, as often as it is repeated; drop the buffer and the call goes ahead. Such a buffer also keeps the feed's C memory alive: close() then closes the feed at once (it hands out nothing more) but frees that memory only when the buffer goes. A message that lay whole in the fed bytes is a view of those bytes, which a buffer made from it keeps alive by itself, so that one never makes a call refuse.

dm = stream.DemuxFeed(view=True)
it = dm.feed(stream.mux_dump([(1, b"abc"), (2, b"def")]))
first = next(it)
kept = bytes(first.payload)
second = next(it)                    # first.payload is released here
kept                                 # → b'abc'
try:
    first.payload[0]
except ValueError:
    pass                             # a released view refuses every use
dm.close()

What it costs. Every item crosses the ctypes boundary, so a message costs microseconds in Python, not the nanoseconds of the C path (doc/10 §8.4). DemuxFeed and the unparsed FrameFeed make one plain C call per item and no callback; DocumentFeed, the parsing FrameFeed and the batch mux_load call back into Python once per event or message. Measured with python/bench/bench_stream.py (CPython 3.14, one core of an Intel i7-2700K pinned with taskset, on a machine shared with other work: load average 3–4, so take the ratios rather than the digits), per message, median of seven runs:

Path 150 B 30 KB 400 KB
mux_load (batch, one callback per message) 4.8 µs 36 µs 383 µs
DemuxFeed, whole buffer, bytes 3.3 µs 7.1 µs 81 µs
DemuxFeed, whole buffer, memoryview 4.6 µs 4.9 µs 57 µs
DemuxFeed, 1460 B pieces, bytes 4.2 µs 130 µs 1.6 ms
DemuxFeed, 1460 B pieces, memoryview 5.7 µs 131 µs 1.6 ms

A small message costs a few microseconds whichever way it is read. A large one fed whole is sliced out of the fed bytes (or viewed in place) instead of copied through a callback, which is the factor of about five. Fed in 1460-byte pieces — one TCP segment's payload — the cost is the feeds, a few microseconds each, twenty of them for a 30 KB message; read from a socket, take the largest recv the transport offers. A memoryview saves the copy only where there is one to save, from a few kilobytes up.

4.8 Live streams: writing a message at a time

mux_dump(..., file=) and dump_documents(..., file=) take every message or document at once. The writer behind mux_dump (and embed_document) gathers its output in a 64 KiB buffer, so a reader at the other end of a socket sees nothing until it fills; dump_documents and frame_documents write each frame as it is made and call the object's flush() once at the end. Two objects in bovnar.stream write as the messages come instead, each handing what it writes to the socket or file before it returns:

Object Writes Per call
MuxWriter(file, *, key="mux", preamble=None, flush_each=True) a document carrying a mux stream, as mux_dump writes it send(channel, payload): one message
FrameWriter(file, *, flush_each=True) a BVF1 frame stream, as frame_documents writes it write(document_bytes) or dump(obj): one framed document

file is a socket (sendall) or a binary file object (write). MuxWriter writes the preamble and opens the stream when it is made (handing them to the object at once with flush_each=True), and with flush_each=True it calls bvnr_write_flush after every send: the message goes to the object, then the object's flush() runs when it has one, so a DemuxFeed at the other end has message N before message N+1 is sent. With flush_each=False it batches into the 64 KiB buffer, and flush() hands over what has gathered. close() — or leaving the with block normally — ends the stream and the document; the object stays open. The bytes are mux_dump's for the same messages and preamble, however often they were flushed:

import io
from bovnar import stream

out = io.BytesIO()
with stream.MuxWriter(out, key="media",
                      preamble={"meta": {"codec": "av1"}}) as mux:
    first_len = len(out.getvalue())     # the preamble is out already
    mux.send(1, b"frame-1")
    sent_len = len(out.getvalue())      # and so is the first message
    mux.send(2, b"audio")

first_len > 0                           # → True
sent_len > first_len                    # → True
same = out.getvalue() == stream.mux_dump(
    [(1, b"frame-1"), (2, b"audio")], key="media",
    preamble={"meta": {"codec": "av1"}})
same                                    # → True

Over a socket, the reader is a DemuxFeed fed whatever recv returns (§4.7):

# check-doc-python: skip
with stream.MuxWriter(sock, key="media", preamble={"meta": meta}) as mux:
    for channel, frame in frames():
        mux.send(channel, frame)        # on the wire when send returns

FrameWriter frames each document as it is written and hands it to the object at once, as frames are never batched; its flush_each only says whether the object's flush() follows each document. A frame stream has no terminator, so close() only flushes the object. MuxWriter.bytes_written and FrameWriter.count say how much has been written:

out = io.BytesIO()
with stream.FrameWriter(out) as frames:
    frames.dump({"id": 1})
    frames.write(b'.id = 2;')
stream.load_documents(out.getvalue())   # → [{'id': 1}, {'id': 2}]
frames.count                            # → 2

The object has to be blocking: a non-blocking socket is refused when the writer is made, since one that took part of a buffer and then raised BlockingIOError would leave the stream cut mid-chunk. (A socket with a timeout is accepted; a timeout fails the writer as any other exception does.) An exception the object raises (a closed socket, a full disk) comes out of the call that pushed — the constructor, send, write, flush or close — unchanged. The writer has failed then: MuxWriter.close() only releases it, and a FrameWriter, which may have written half a frame, refuses further documents. Leaving a MuxWriter's with block by an exception does not end the stream either, so a reader sees it cut off rather than complete. The object's own write() and flush() may not call back into the writer that called them — send, write, flush or close it, or for Writer.to_stream write a value: that raises BovnarArgumentError, where the bytes written from there would land inside those being handed over. Writer.to_stream(...).flush() (§12.2) does the same for a document written value by value.

What it costs. Measured with python/bench/bench_stream.py on the machine of §4.7, into a socket-like object whose sendall takes the bytes, per message, the median over its runs:

Path 150 B 30 KB 400 KB
mux_dump (batch, to bytes) 7.6 µs 29 µs 287 µs
MuxWriter, flush_each=False 2.2 µs 10 µs 114 µs
MuxWriter, flushed per message 5.5 µs 12 µs 126 µs

A flush per message costs a ctypes call and a Python call of the object's sendall (with the copy of the bytes it is handed) for every message, against one per 64 KiB batched: about 3 µs on a small message, which is the price of the reader having it at once. Large messages are dominated by the copy either way.

4.9 Canonical form

bovnar.canonicalize(data, *, pretty=False, **options) re-serialises a document from its verified events through the C library's canonicalising observer (bvnr_canon_observer_*, doc/08 §3.6) and returns the bytes; bovnar.canonicalize_to(data, out, *, pretty=False, **options) writes them to out — a writable binary file object, a socket or a bytearray — as they are made, in 64 KiB pieces. data is bytes, or a socket or binary file object read to its end as the parse pulls it, so neither the input nor the output need be held whole.

import bovnar

doc = b'.a = 1 ;  # one\n.b = { .c = "x"; };'
canon = bovnar.canonicalize(doc)
canon                                # → b'.a=<uint:64,_10,no_unit>1;.b={.c=<utf8>"x";};'
bovnar.canonicalize(canon) == canon  # → True
bovnar.canonicalize(b'.b={.c="x";};.a=1; ') == bovnar.canonicalize(b'.a=1;.b={.c="x";};')  # → False

It is the form bovnar events -d prints (-p for pretty=True): the compact one is a single line with no whitespace outside literals, each value written with the annotation the reader gives it (1 as <uint:64,_10,no_unit>1). Two documents that differ only in layout, comments and the spelling of separators canonicalise to the same bytes, and canonicalising the output again gives it back unchanged; the order of the keys is kept, so documents that differ in it stay apart. Units are written as the document spelled them: this is not bovnar pretty-print --canonical, which writes through a writer under UnitFlags.REDUCE | UnitFlags.NUM_CANONICAL and folds them to one form. A leading #!bovnar M.N directive is kept — for a stream it is found in the first bytes pulled, before the reader sees them.

The keywords are the read options of Reader.read_mem (bovnar.READ_OPTIONS, §11.2), all 0 / False by default. A document the reader refuses raises BovnarParseError with the reader's code and position. Under continue_on_error a document the reader had to recover from raises it too, with the first error recovered from: the observer writes what it is fed, and the statement a recovery leaves without its value would make the output unreadable. An exception the input or out raises comes out unchanged; after an error out may hold the start of the output.

The observer's C function is installed as the reader's on_verified itself, with the observer as its userdata, so no Python runs per event: Python is called for the output a 64 KiB piece at a time, and for the input of a stream a pull at a time.

5.1 The unit-profile notations (spec 1.2)

These notations are spec 1.2: in a document they need a #!bovnar 1.2 directive, while the API entry points below have no document and take them unconditionally. parse_unit takes a profile notation as readily as the native one, and returns the same ValueUnit either way — so everything else in this chapter works on the result unchanged. Seven namespaces are accepted — ucum:, unece:, qudt:, qudt-qk:, udunits:, om: and cf: — but each is a compile-time switch, so which of them a given build carries is a question to ask rather than assume; see available_profiles() below. Helpers cover what a caller needs around them:

import bovnar

vu = bovnar.parse_unit("ucum:mm[Hg]")
bovnar.unit_to_str(vu)              # → "mmHg"   — the native canonical form
bovnar.unit_to_ucum(vu)             # → "mm[Hg]" — back to a UCUM code
bovnar.units_compatible(vu, bovnar.parse_unit("k~Pa"))   # → True

# Which profiles THIS build carries. Each namespace is a compile-time switch,
# so a wheel may have been built without some of them. parse_unit raises the
# same BovnarArgumentError("Invalid unit string: ...") for an absent namespace
# as for a bad unit; unit_error_code() below is what tells the two apart (49
# against 32).
bovnar.available_profiles()
# → ('ucum', 'unece', 'qudt', 'qudt-qk', 'udunits', 'om', 'cf')

# The same unit in other vocabularies — all one ValueUnit
kg = bovnar.parse_unit("k~g")
bovnar.unit_to_profile("ucum",    kg)   # → "kg"
bovnar.unit_to_profile("unece",   kg)   # → "KGM"
bovnar.unit_to_profile("qudt",    kg)   # → "KiloGM"
bovnar.unit_to_profile("udunits", kg)   # → "kg"

iu = bovnar.parse_unit("ucum:[IU]/mL")
bovnar.unit_is_profile_only(iu)     # → True  — no native spelling exists
bovnar.unit_to_str(iu)              # → "ucum:[IU].mL-1"

box = bovnar.parse_unit("unece:XBX")
bovnar.unit_is_profile_only(box)    # → True  — a countable package
bovnar.unit_to_str(box)             # → "unece:XBX" — in its OWN namespace

bovnar.unit_error_code("ucum:B[SPL]")   # → 50 (ErrorCode.UNIT_PROFILE_UNSUPPORTED)
bovnar.unit_error_code("udunits:days since 1970-01-01")
                                        # → 50 — valid UDUNITS, not carryable
bovnar.unit_error_code("nosuch:m")      # → 49 (ErrorCode.UNIT_PROFILE_UNKNOWN)
bovnar.unit_error_code("m/s")           # → 0  (ErrorCode.NONE — it parses)

unit_to_profile and unit_to_ucum raise rather than inventing a code, in three situations. A native unit outside that vocabulary's transliteration table has no form in it — the Old German units, the water-hardness degrees, the turbidity kinds and every currency. An opaque unit belonging to a different profile has none either: [IU] is UCUM's, so unit_to_profile("unece", …) refuses it. And a flat vocabulary (unece, qudt, qudt-qk, om) can spell only a single component — no product, quotient or exponent, though a prefixed one is fine (k~g is unece:KGM) — because a flat code is one whole token with no operator to build it out of — so k~m/h has no UNECE form even though unece:KMH parses to exactly it.

In a document the notation additionally requires a #!bovnar 1.2 directive; without it loads raises with unit_illegal. parse_unit has no document and therefore no declared version, so it accepts the notation unconditionally.

See Unit Profiles for the transliteration tables and the codes that have no representation.

5.2 Extended unit functions

The following functions operate on ValueUnit objects and are available both from the top-level bovnar namespace and from bovnar.units. Each of them — and unit_to_str, unit_to_profile, unit_to_ucum, unit_is_profile_only, the pint and NumPy bridges, write_array(vu=) and a want_unit callback's return value — takes a Unit (what Quantity.unit and Unit.parse() hand out) wherever it takes a ValueUnit, so unit_to_str(q.unit) needs no .raw.

from bovnar import (
    unit_valid, unit_prefix_factor, unit_prefix_exponent,
    prefix_unit_valid,
    unit_to_si_factor, units_compatible, units_equal,
    unit_convert_factor, unit_dimension_vector,

# Validate a ValueUnit struct
ok = unit_valid(vu)                   # True when vu is structurally valid

# Prefix scale factor (SI or IEC) for a ValueUnit
f = unit_prefix_factor(vu)            # e.g. 1000.0 for k~m, 2**30 for Gi~B

# Prefix exponent (base-10 for SI, base-2 for IEC)
e = unit_prefix_exponent(vu)          # e.g. 3 for kilo, -3 for milli, 30 for gibi

from bovnar import ValueUnitPrefix, IECPrefix, BaseUnit

# conv.factor, conv.is_affine, conv.affine_offset

ok = units_compatible(vu_a, vu_b)     # b vs B is False — the dimensions agree,
                                      # the kinds do not

# c.factor, c.requires_affine, c.ok — ok is False (and factor 0.0) for an

# 7-element SI dimension exponent vector [m, kg, s, A, K, mol, cd]
dims = unit_dimension_vector(vu)       # e.g. [1, 0, -1, 0, 0, 0, 0] for m/s

# Fold every prefix out and combine repeated bases. NOT the named-SI collapse:
# unit_reduce(parse_unit("k~g·m/s²")).unit is "m·g/s²", and it is

# Convert a scalar value between units (handles affine conversions)

SI_DIM_NAMES is the ordered tuple ('m', 'kg', 's', 'A', 'K', 'mol', 'cd') — the index positions used by unit_dimension_vector.

5.3 UnitFlags

from bovnar import UnitFlags   # also from bovnar.units

UnitFlags.NONE      # 0 — no special formatting
UnitFlags.REDUCE    # reduce to a canonical named SI unit before serialising
UnitFlags.ASCII_EXP # use ^N exponent notation instead of Unicode superscripts
UnitFlags.NUM_CANONICAL  # writer only: a float REDUCE rescaled keeps float shape

The same flags configure a writer: Writer.to_mem(unit_flags=UnitFlags.REDUCE) (and to_fd / to_file) rewrites each unit as it is written and rescales the value with it — 2.5 k~g goes out as <float:64,g> 2500. NUM_CANONICAL is meaningful only there: it appends .0 to a rescaled float that came out as an integer string, and writes each annotation in one form (the width written out, a default _10 base and no_unit left out), so the canonical document mode lands on one spelling.

UnitFlags.REDUCE returns the reduced unit, not a rescaled value. Reduction folds every prefix out, so unit_to_str_ex(parse_unit("k~g"), UnitFlags.REDUCE) is "g" — a string denoting a quantity 1000× smaller than the unit you passed. Moving the value with it is your job. (The writer does it for you; nothing else does.)

Do not use unit_reduce(vu).scale for that. It is the scale to the fully reduced unit, and this function does not always emit the fully reduced unit: where the reduction lands on a named SI unit the formatter re-attaches the prefix. k~N comes back "k~N" with nothing to rescale while unit_reduce still reports 1000.0, and k~g comes back "g" where the 1000.0 must be applied. The two are indistinguishable from outside — both a lone unit carrying a kilo prefix — so take the scale from the unit that is actually emitted:

python emitted_str = unit_to_str_ex(vu, UnitFlags.REDUCE) emitted = parse_unit(emitted_str) value *= convert_value(1.0, vu, emitted) # 1.0 for k~N, 1000.0 for k~g

The collapse never substitutes one named unit for another, so a Sv stays a Sv rather than becoming a Gy. A lone base at an exponent other than 1 does still collapse (s⁻¹ → "Hz", m~s⁻¹ → "k~Hz"), and a reduction whose summed exponent leaves the ±100 range (BVN_EXPONENT_MIN/MAX) raises BovnarArgumentError instead of returning a unit that lost a dimension — m⁵⁰·m⁵⁰ reduces to m¹⁰⁰, m⁵⁰·m⁵¹ raises.

UnitFlags is an IntFlag and its values may be OR-combined:

s = unit_to_str_ex(vu, UnitFlags.REDUCE | UnitFlags.ASCII_EXP)

from bovnar import ValueUnitPrefix, SIPrefix, IECPrefix

5.5 Inline unit suffix

In addition to the unit embedded in a type annotation (<float:64,m/s>), the Bovnar format supports an inline unit suffix placed directly after a scalar value, before the terminating ;:

.speed = 9.81 m/s;           # inline suffix, no annotation
.mass  = <float:64> 70.5 k~g;# annotation without unit, inline adopted
.dist  = <float:64,m> 1.5 m; # annotation and inline both say 'm' — valid

From the Python layer, inline and annotation units are identical: both reach the application as data.value_unit inside the Event.DATA payload. No extra code is required to consume inline units.

The validator raises ErrorCode.UNIT_MISMATCH (38 / BovnarParseError) when an inline suffix is present and a type-annotation unit is also present but the two do not resolve to the same value_unit_t. Inline unit suffixes inside array elements always raise ErrorCode.UNEXPECTED_INPUT_BYTE.

5.6 UnitPolicy — validation and conversion without a callback

Reader.set_unit_policy states what the document must contain and what unit values should arrive in. Everything is unit text, so unlike want_unit it costs no per-value trampoline across the FFI boundary — the C side parses the strings once, when the policy is set.

from bovnar import Reader, UnitPolicy

with Reader() as r:
    r.set_unit_policy(UnitPolicy(
        targets=["m/s", "°C"],      # convert to the first one that fits
        normalise_si=True,          # ...and everything else to SI base units
        leave_inexact=True,         # step over what cannot be exact
        require_unit=True,          # reject any bare numeric value
    ))
    r.read_file("sensors.bvnr", on_verified=handler)

A policy survives re-reading the same reader on another document — it describes the consumer, not the document — and set_unit_policy(None) clears it. Every unit string is parsed by the call, so a typo raises BovnarArgumentError before a byte is read, and a rejected policy leaves the previous one in force.

Conversion. Each numeric value takes the first target it can validly convert to, so order is significant: ["m", "k~m"] never selects k~m. A value that matches nothing, or that is already in the unit a target names, arrives untouched — data.converted is what tells the two apart. Each target may carry its own output base as ("m", 16).

normalise_si catches whatever the targets did not, delivering it in coherent SI base units with prefixes folded out. Currencies and every dimensionless unit (%, ppm, dB, pH, rad, °) are left as written rather than reinterpreted.

A value with no unit only ever matches a target that is itself no_unit. A bare number is dimensionally compatible with % and ppm, so without that fence a policy naming "%" would deliver 0.25 as 25.

Exactness. Nothing approximate is ever delivered. leave_inexact=True hands over a value the conversion cannot deliver exactly — an irrational factor, a non-terminating expansion (42 km/h is 35/3 m/s), an exponent past the work limit — in its native unit instead of raising. It applies only to policy-chosen targets; a want_unit hook keeps its strict all-or-nothing contract.

Validation. require_unit rejects a document containing any bare numeric value; require_dimension_of=["m"] requires every numeric value to be validly convertible to at least one listed unit. Both are evaluated on the unit the document wrote, before any conversion, and both raise ErrorCode.UNIT_MISMATCH.

Per-field rules name one field by its key path, and are consulted before everything else:

from bovnar import Reader, UnitPolicy, UnitRule, dom_parse

policy = UnitPolicy(rules=[
    UnitRule(".inlet.temperature", "°C"),                  # convert this field
    UnitRule(".inlet.*", "m", convert=False),              # assert the subtree
])

A path ending in ".*" names a subtree at any depth, and a prefix only matches at a component boundary (".in.*" does not claim ".inlet.a"). Unlike a whole-document target, a rule is an assertion: a value it cannot be applied to raises UNIT_MISMATCH, because silence would defeat the point of naming the field. convert=False asserts without converting.

The DOM takes the same policy, so a random-access consumer gets both halves:

doc = dom_parse(text, UnitPolicy(rules=[UnitRule(".inlet.temperature", "°C")]))
doc.lookup(".inlet.temperature").as_float()    # 100.0, from a document in °F

A value the policy converted is STORED converted — digits, unit and base — and an integer that converts to a fraction (5 g in kilograms is 0.005) is stored as a float. A policy the library refuses raises BovnarArgumentError — the same error, naming the same entry, as Reader.set_unit_policy — before anything is parsed, rather than a parse error, so a mistake in the policy is never mistaken for a fault in the document.

The writer takes the same policy, validation half only. A reader can only reject a document somebody already wrote; Writer.set_unit_policy is what stops a bare number reaching the file:

from bovnar import Writer, UnitPolicy

w = Writer.to_mem()
w.set_unit_policy(UnitPolicy(require_unit=True, require_dimension_of=["m"]))
w.write_float("tank_level", 12.0, unit_str="in")   # a length — written
w.write_float("spare", 0.25)                        # BovnarWriteError,
                                                    # code UNIT_MISMATCH

A policy carrying targets, normalise_si, base or leave_inexact raises BovnarArgumentError there rather than being half-honoured: write-side unit rewriting is UnitFlags.REDUCE's job — open the writer with Writer.to_mem(unit_flags=UnitFlags.REDUCE) — and two rewriting modes with different rules about exactness is how a document ends up meaning two things.

Module-level helpers back the same decisions outside the reader:

from bovnar import (units_equal, units_compatible, units_convertible,
                    unit_si_normal_form, parse_unit)

# units_compatible is the wrong screen for a conversion target: a currency
# carries no dimension, so it is reported incompatible with itself.
units_compatible (parse_unit("k~$USD"), parse_unit("$USD"))   # → False
units_convertible(parse_unit("k~$USD"), parse_unit("$USD"))   # → True

unit_si_normal_form(parse_unit("in"))   # → m
unit_si_normal_form(parse_unit("g"))    # → k~g  (the SI base unit for mass)
unit_si_normal_form(parse_unit("%"))    # → None (dimensionless)
unit_si_normal_form(parse_unit("lm"))   # → None (carries the steradian's kind)

Three questions, in decreasing strictness. units_equal asks whether the two are the same unit, units_compatible whether their dimensions and quantity kinds line up, units_convertible whether a conversion can actually be performed. Only the last is the right screen for a conversion target.

units_equal(parse_unit("m"), parse_unit("m"))       # → True
units_equal(parse_unit("m"), parse_unit("k~m"))     # → False — convertible, not equal
units_equal(parse_unit("N"), parse_unit("k~g·m/s²"))  # → False — same SI form
units_equal(parse_unit("mmHg"), parse_unit("ucum:mm[Hg]"))   # → True

units_equal is also what == means between two units, whether they are ValueUnits or Units, and the two hash alike so they share a dict:

parse_unit("m") == parse_unit("m")                  # → True

The hash follows the equality in the one place the two could part: a component with no prefix is the same component whether its prefix system says SI or IEC, so parse_unit("B") and make_unit_iec(BaseUnit.BYTE) are equal and one dict key.

A Unit also compares equal to a string that parses to it (q.unit == "k~m"). That is a convenience for comparison only and is not hash-compatible — "km", "k~m" and "ucum:km" are three strings with three hashes and one unit — so Unit.parse("m") in {"m"} is False. Key a dict or set on Unit objects (or on str(unit)), never on a mix of the two.

Unit.convert_factor(other) and Unit.factor return a bare number, so they raise BovnarArgumentError where there is no such number: an affine pair (°C → K) has no multiplicative factor and an affine unit no SI factor. Use convert_value() there, or unit_to_si_factor() for the scale and the offset.

That comparison used to be False. ValueUnit is a ctypes.Structure, which defines no __eq__, so == fell back to identity — see the note in §5.7 on why the raw struct is worth knowing about at all. ValueTypeSpec carried the same gap and compares by value now too, so node.value_type == other.value_type answers the question it looks like it is answering.

5.7 Building a ValueUnit

parse_unit builds a unit from text. To build one programmatically — without going through the notation — use the make_unit_* constructors, exported from the top-level bovnar namespace and from bovnar.structs.

from bovnar import (make_unit_si, make_unit_iec, make_unit_compound,
                    make_unit_none, make_unit_dimensionless,
                    BaseUnit, SIPrefix, IECPrefix, Exponent, unit_to_str)

make_unit_si(BaseUnit.GRAM, SIPrefix.KILO)              # k~g
make_unit_si(BaseUnit.METER, exp=Exponent.SQUARE)       # m²
make_unit_iec(BaseUnit.BYTE, IECPrefix.GIBI)            # Gi~B

make_unit_compound([                                    # k~g·m/s²
    {"base": BaseUnit.GRAM,   "si_prefix": SIPrefix.KILO, "exp": Exponent.LINEAR},
    {"base": BaseUnit.METER,                             "exp": Exponent.LINEAR},
    {"base": BaseUnit.SECOND,                            "exp": Exponent.NEG_SQUARE},
])

prefix and exp default to none and linear, so a plain base unit is make_unit_si(BaseUnit.METER). A make_unit_compound component accepts the keys base, exp, si_prefix and iec_prefix — note that the compound form spells the prefix key out, where the scalar constructors take it positionally.

make_unit_none() and make_unit_dimensionless() are not the same thing, even though both render as no_unit. The first is a unit struct with no components at all — a value carrying no unit. The second is one component whose base is NONE — a value carrying no_unit explicitly. That is exactly the pair UnitPolicy(require_unit=True) refuses together (§5.6), and the distinction survives a round trip:

unit_to_str(make_unit_none())            # 'no_unit'
unit_to_str(make_unit_dimensionless())   # 'no_unit'
bytes(make_unit_none()) != bytes(make_unit_dimensionless())   # True

5.8 Validators and literal helpers

bovnar.literals binds the C library's checks and literal helpers (bovnar.h): the tests the writer applies to keys, symbols, references and numbers, the integer and float parsers and formatters behind it, and the parser of a type annotation. Each function is the C function of the same name without its bvn_ prefix (escape_repl_table is bvn_get_escape_repl_table), and answers as it does. Text holding NUL is none of the things they check: a validator answers False for it, a parser raises — except validate_string, which takes bytes and checks only that they are UTF-8, so NUL passes.

Type annotations. parse_type_annotation(text) parses the text between the angle brackets, as the reader does, into a frozen TypeAnnotation of value_type (a ValueTypeSpec), unit (a ValueUnit, with no components when there is no unit or it is spelled no_unit) and unit_source (the unit parameter as written, '' when there is none):

from bovnar import literals, BovnarParseError

a = literals.parse_type_annotation("uint:32,_16,k~g")
a.value_type.width, a.value_type.base     # → (32, 16)
a.unit                                    # → "k~g"
a.unit_source                             # → "k~g"
literals.parse_type_annotation("float:64,ucum:mL{total}").unit_source   # → "ucum:mL{total}"

try:
    literals.parse_type_annotation("uint:8,_16,_16")    # a base given twice
except BovnarParseError as e:
    refused = e.code
refused.name                              # → "ILLEGAL_VALUE_TYPE"

6. Quantity

Quantity is a typed, unit-annotated scalar value that preserves the original text representation, type width, numeral base, and physical unit across a loads / dumps round-trip.

from bovnar import Quantity, ValueTypeSpec, ValueUnit
from bovnar.enums import ValueTypeFamily

6.1 Construction

Quantity is normally produced by loads(..., typed=True) rather than constructed by hand, but direct construction is supported:

from bovnar.structs import make_type_spec
from bovnar.enums   import ValueTypeFamily

vt = make_type_spec(ValueTypeFamily.FLOAT, 32)
q  = Quantity('101325.0', vt)          # dimensionless
q2 = Quantity('9.81',     vt, vu)      # vu is a ValueUnit, e.g. from parse_unit

For exact numeric input there is also the Quantity.from_number constructor, which stores the value as an exact decimal literal (so writing it with dumps is lossless to the format's precision):

from decimal import Decimal
from fractions import Fraction

Quantity.from_number(Decimal('19.99'))                          # float_dec:64
Quantity.from_number(Decimal('1.1'), family=ValueTypeFamily.FLOAT, width=128)
Quantity.from_number(Fraction(837, 256),
                     family=ValueTypeFamily.FLOAT_FIX, width=32, frac=8)

It accepts a Decimal, Fraction (must be a terminating decimal), int, str (a verbatim literal), or float (only as precise as the double), and validates the width for the chosen family. A str must be a decimal number literal in the format's own grammar — digits with an optional leading -, . and exponent (1.5, -2e-3, .5), or nan, inf, ninf — so '', 'abc', ' 1' and '+1' raise BovnarArgumentError here rather than failing later in dumps. For float_dec it also refuses a finite value past the width's range — Decimal('1e400') does not fit float_dec:64 and would materialise to infinity — and a non-finite float is stored under the format's own spelling (inf, ninf, nan).

6.3 Lossless numeric access (float_dec, float_fix, float:128/256)

q.value decodes through a C double, which loses precision for the decimal-float, fixed-point, and wide binary-float families. The accessors above instead use the verbatim literal text (and bovnar's arbitrary-precision bvn_float), so the full precision the format carries is reachable from Python:

q = bovnar.loads(b'.p=<float_dec:64> 3.141592653589793238462643383279503;',
                 typed=True)['p']
q.value          # 3.141592653589793   (lossy C double)
q.decimal      # Decimal('3.141592653589793238462643383279503')  (exact literal)
q.stored_value # Decimal('3.141592653589793')  (the decimal64-rounded value)

f = bovnar.loads(b'.x=<float_fix:32,q8> 3.27;', typed=True)['x']
f.fraction     # Fraction(837, 256)
f.fixed_point  # (837, 8)

These materialise over the full representable range, including exponents the C parser cannot otherwise reach (beyond ~1e9865). decimal / fraction work at every binary width bovnar allows (16, or a multiple of 32 up to 32768); the bit-exact stored_value / ieee_bits apply to the IEEE encodings (float:16/32/64/128/256), which are also exposed directly as bovnar.BvnFloat.

6.4 dumps() integration

_emit_value dispatches on Quantity before the plain int / float path, so any dict that came from loads(..., typed=True) can be passed directly to dumps() and will produce identical output:

bvnr  = b".speed = <float:32,m/s> 9.81;"
doc   = bovnar.loads(bvnr, typed=True)
out   = bovnar.dumps(doc)
assert out.strip() == bvnr.strip()

The annotation is suppressed when _needs_annotation returns False — i.e. when the type is FLOAT:64 with no unit and no non-decimal base (matching the C library's own default-annotation omission rules).

dumps() also accepts bare decimal.Decimal (written as an exact float_dec:64 literal) and terminating fractions.Fraction values directly — a non-terminating fraction (e.g. Fraction(1, 3)) raises BovnarArgumentError, as does a Decimal outside the range of float_dec:64. A list whose elements are all Decimal / Fraction is written under one <float_dec:64> annotation, so the elements mean what the scalars mean.

Arrays of Quantity. An array has one annotation. Elements that agree on type and unit are written under it. Elements that agree on the unit but not the type — or that carry no unit and differ in type, [<uint:8> 1, <float:64> 2.5] — are each written under their own annotation, as they were read. Elements that carry different units have no valid form and raise.

Octet streams. loads() returns an octet stream as bytes, and dumps() writes bytes / bytearray / memoryview back as one, so a document holding one round-trips.

What "can be passed directly to dumps()" does not promise is that the result passes the document tier: dumps() writes what loads() reads, and loads() reads heterogeneous and ragged arrays that dom_parse and bovnar validate refuse. See the note in §4.1.

6.5 Civil time and calendars

A datetime value is a count of seconds since its epoch (§19). bovnar.timekeeping turns such counts into civil dates and times and back, and carries the rest of the C library's calendar: bvn_datetime.h and bvn_gregorian_date.h. Every result is computed by the C functions, so the binding gives the answers the reader and writer use when they read and print an ISO literal. Nothing is read from the host's time zone or clock.

import bovnar
from bovnar.timekeeping import (
    CivilDateTime, Epoch, GregorianDate, easter_sunday, epoch_seconds_to_utc,
    tai_second_is_dls_in_europe, tai_seconds_to_local_time, tai_seconds_to_utc,
    utc_to_tai_seconds,

q = bovnar.loads(b'#!bovnar 1.1\n.t = <datetime:64,tai> 1861920036;',
                 typed=True)['t']
str(q.to_civil())                                   # → '2016-12-31T23:59:60'

str(epoch_seconds_to_utc(1750000000, Epoch.UNIX))   # → '2025-06-15T15:06:40'

t = utc_to_tai_seconds(CivilDateTime(2024, 7, 1, 12))

str(easter_sunday(2025))                            # → '2025-04-20'
GregorianDate(2024, 3, 29).is_federal_holiday_in_germany()      # → True  (Good Friday)
str(GregorianDate(2024, 3, 5).last_banking_day_in_month())      # → '2024-03-28'

The types. GregorianDate(year, month, day) is a date of the proleptic Gregorian calendar (bvn_gregorian_date_t), with astronomical years (1 BC is year 0) from YEAR_MIN to YEAR_MAX, about ±2.5·10¹⁶. The constructor takes only a real date; GregorianDate.normalize(year, month, day) carries an out-of-range month or day into the next field instead, as mktime does. Its leap, wday (0 = Sunday) and yday (0 = 1 January) come from the library. CivilDateTime(year, month, day, hour=0, minute=0, second=0) adds a time of day (bvn_datetime_t) and checks hour 0–23, minute 0–59 and second 0–60; .date is its GregorianDate and .mjd the date's Modified Julian Day. Both are frozen and hashable, compare with the C equality functions, order chronologically, print as ISO 8601 (2016-12-31T23:59:60) and convert to datetime.date / datetime.datetime with to_date() / to_datetime() where those can hold the value (years 1–9999, no leap second). Epoch is bvn_epoch_t: each member's value is its epoch's MJD, so Epoch(q.epoch_mjd) is the epoch of a datetime Quantity, and an epoch argument may also be given as that int or as the library's name ("unix", "y2000", …). Epoch.from_name(name) resolves such a name through the library (bvnr_datetime_epoch_index, bvnr_datetime_epoch_mjd): Epoch.Y2000 for "y2000", Epoch.UNIX for "", None for a name it does not know.

7. write_array helper

write_array is a high-level helper exported from the top-level bovnar namespace. It handles both flat and multi-dimensional arrays.

from bovnar import write_array, Writer
from bovnar.structs import make_type_spec, make_unit_si
from bovnar.enums import ValueTypeFamily, BaseUnit

with Writer.to_mem() as w:
    # Single-row array
    write_array(w, "primes", [2, 3, 5, 7])

    # Multi-row array (rows separated by /)
    write_array(w, "matrix", [[1, 2, 3], [4, 5, 6]])

    # Typed array: whole-array type annotation
    vt = make_type_spec(ValueTypeFamily.UINT, 16)
    write_array(w, "ports", [80, 443, 8080], vt=vt)

Element types accepted per element: int, float, str, bool, None, bytes (an octet stream), dict (written as a struct), or nested list/tuple (written as a nested array). When rows is a flat sequence it is treated as a single-row array; when all top-level elements are themselves list or tuple it is treated as a multi-row array. Any other iterable (a generator, a range) is materialised first.

With vt, every element is held to it. An int under an integer annotation is checked against the width and written in the annotation's base — quoted where the base requires it, so 255 under <uint:16,_16> is "ff". An element the annotation cannot describe — 80800 under <uint:16>, a float or a str under an integer type, a dict under any — raises BovnarArgumentError instead of producing a document nothing reads. None is a null hole and is always allowed; a Quantity element carries its own literal and is written as it is. vu takes a ValueUnit or a Unit.

8.1 Prefixes ride in the unit, never the magnitude

bovnar's k~m maps to pint kilometer — the prefix is kept inside the unit name, never folded into the magnitude. A wrapped value is therefore returned unscaled, so a wrapped numpy array is never silently rescaled.

8.2 Affine temperature units

Offset/affine scales (°C, °F, Réaumur, Delisle, Newton, Rømer) cannot carry a prefix or exponent — pint forbids it and bovnar never emits it. A prefixed or exponentiated affine unit raises BovnarArgumentError rather than a cryptic pint error.

to_pint / to_pint_unit take a ValueUnit or a Unit, so bovnar.to_pint(q.value, q.unit) works on a typed value as it stands. A unit pint cannot name raises BovnarArgumentError: the profile-only units, and anything carrying the IEC prefixes Ri~ / Qi~, which pint does not define.

8.3 Validation

from_pint / from_pint_unit validate the resulting ValueUnit by default (validate=True); a pint unit that maps to a structurally invalid bovnar unit (e.g. a prefix not permitted on that base) raises BovnarArgumentError. pint units with more than MAX_UNIT_COMPONENTS (32) components, non-integer exponents, or exponents outside [EXPONENT_MIN, EXPONENT_MAX] = [-100, 100] also raise. Those two bounds are imported from bovnar.structs and bovnar.enums rather than restated in the bridge: they were once written out as 8 and ±9, the values the C library had when the bridge was first written, and stayed behind when it grew — so from_pint refused units to_pint had just produced, and said the old numbers were bovnar's range.

8.4 Registry control: build_registry

A module-level default pint.UnitRegistry is built on first use. To share a registry across calls — or to register bovnar's custom units onto your own — pass ureg=:

from bovnar._pint_units import build_registry, is_currency_unit, is_kind_scale

ureg = build_registry()                       # fresh registry with bovnar units
ureg = build_registry(my_existing_registry)   # extend an existing one
ureg = build_registry(with_currencies=False)  # skip the currency dimensions
ureg = build_registry(isolate_kinds=False)    # alias kinds onto pint's natives

qty  = bovnar.to_pint(5.0, vu, ureg=ureg)

build_registry registers bovnar's custom physical-unit definitions — units where pint's own definition differs or is missing (e.g. bvnr_gauss, bvnr_var, the historical German units) — plus, by default, the ISO 4217 + crypto currencies as custom dimensions. is_currency_unit(unit) reports whether a pint unit involves a currency dimension (holds for products such as USD/year).

8.5 Quantity kinds: isolate_kinds

Bovnar tracks quantity kinds for units that carry no SI dimension yet are not interchangeable — bit vs byte, an angle vs a plain count, dB vs Np vs pH, one kind per turbidity method, and practical salinity. pint has no such concept: to pint they are all dimensionless, so left to itself it will convert an NTU into an FNU, a byte into 8 bits or a pH into a percentage — precisely the answers Bovnar exists to withhold.

build_registry therefore gives each kind its own pint dimension, the same device the currency table uses to stop 100 USD becoming 100 EUR. pint then enforces Bovnar's rule natively:

ureg = build_registry()                       # isolate_kinds=True by default
q    = bovnar.to_pint(4.2, bovnar.parse_unit("NTU"), ureg=ureg)

q.to("bvnr_fnu")        # pint.DimensionalityError — as bovnar refuses it
q.to("dimensionless")   # pint.DimensionalityError
q.to("bvnr_ntu")        # 4.2 — a conversion within the kind is fine

Conversions within a kind keep working, because that is what a shared dimension means: m~NTU → NTU, ° → rad (1 rad = 57.29578°), sr = rad². bovnar._pint_units.is_kind_scale(unit) reports whether a pint unit carries one of these dimensions, as is_currency_unit does for money.

The cost is interoperability with pint's native units: a Bovnar-derived byte no longer converts to pint's megabyte, nor a Bovnar radian to pint's degree. If you need that more than you need the refusals:

ureg = build_registry(isolate_kinds=False)    # alias onto pint's natives

which restores both the interop and pint's permissiveness. The default is fidelity.

8.6 Semantic caveats

What survives kind isolation is recorded in bovnar._pint_units.SEMANTIC_CAVEATS: DECIBEL, NEPER and PH_SCALE, whose labels and refusals now match but whose arithmetic does not (pint will add two decibels; 20 dB is a ratio of 100, not twice 10 dB), and VAL, where the divalent water-analysis convention is a fact no unit system can infer. Consult that dict when exact round-trip semantics matter.

The mapping is not 1:1 by construction (bovnar b=bit vs pint barn, R=roentgen vs pint's gas constant). The translation table is locked against silent drift by TestUnitTableIntegrity, which re-derives every physical unit's dimension and magnitude from bovnar and asserts the pint bridge reproduces both, and by TestPintAgreesWithBovnarOnWhatConverts, which asserts that pint refuses every conversion bovnar refuses — the invariant that was missing when pint was quietly the more permissive of the two.

9. NumPy bridge

The NumPy bridge converts between bovnar arrays and numpy.ndarray. numpy is an optional dependency, imported lazily on first use. Install with pip install "bovnar[numpy]" (or bovnar[all]).

All five functions are exported from the top-level bovnar namespace (and from bovnar._numpy):

Function Direction Description
to_numpy(src, *, dtype=None, return_unit=False) bovnar → numpy Array → ndarray (optionally (ndarray, unit_str))
to_pint_array(src, *, dtype=None, ureg=None) bovnar → pint Array → pint Quantity (ndarray data + unit)
from_numpy(writer, key, arr, *, unit=None, float_format=None) numpy → bovnar Write an ndarray into a Writer
from_pint_array(writer, key, qty) pint → bovnar Write a pint Quantity (magnitude + unit) into a Writer

9.1 Reading: to_numpy

src is either a DomNode for an ARRAY (random-access, from dom_parse) or the nested list/tuple that loads(..., typed=True) produces. Both /-separated rows and bracket nesting collapse to the same ndarray shape.

import bovnar

# from a typed loads() result
doc = bovnar.loads(b'.a=<uint:8>[1,2,3];', typed=True)
arr = bovnar.to_numpy(doc['a'])               # dtype uint8

# with the whole-array unit
arr, unit = bovnar.to_numpy(
    bovnar.loads(b'.a=<float:32,m/s>[1,2,3]/[4,5,6];', typed=True)['a'],
    return_unit=True)                         # unit == 'm/s', arr.shape == (2, 3)

# from a DOM node
arr = bovnar.to_numpy(bovnar.dom_parse(b'.a=<sint:16>[10,-20,30];')['a'])

The bovnar (family, width) maps directly to the numpy dtype (uint:8 → uint8, float:32 → float32, …). Pass dtype= to coerce.

The families with no exact native numpy dtype — float_dec, float_fix, and the wide binary floats float:128/256 (and any width above 64) — decode to an object array of exact decimal.Decimal on the typed (loads(..., typed=True)) path, which is lossless; pass dtype='float64' for the lossy native conversion. The DOM (dom_parse) path only has a C double for these, so it raises and points you at the typed path or dtype='float64'. Integers wider than 64 bits need dtype=object, which gives an exact object array of Python ints; without it to_numpy raises BovnarArgumentError. An empty DOM array takes its dtype (and unit) from its annotation — <sint:32> [] is an int32 array of shape (0,) — since it has no element to infer one from; an empty array with no annotation is float64, as numpy infers.

A datetime array on the unix epoch (spec 1.1) maps to/from datetime64[s] — the integer epoch-seconds carrier is unix-relative, so it round-trips losslessly. A non-unix epoch (tai, gps, …) is not unix-relative, so to_numpy refuses it (mapping it to datetime64 would mis-date every value) and points you at dtype='int64' for the raw seconds. On the write side a datetime64[*] array is coarsened to whole seconds and written as <datetime:64> (the unix epoch is the default and is not spelled out); NaT has no bovnar representation and is rejected, and array_to_bvnr prepends the #!bovnar 1.1 directive so its output re-parses.

Strict by default:

  • an array that mixes numeric encodings (e.g. uint:8 and float:64) raises unless you pass dtype= to coerce to one;
  • a Bovnar array is rectangular and homogeneous at the document tier (dom_parse, bovnar validate), so a DomNode always yields a regular ndarray. The streaming tier — loads(), and therefore dumps() — does not enforce that (see §4.1): a ragged typed list raises here unless you pass dtype=object;
  • a null element cannot fill a dtype with no null slot — integer, bool, or string (which would otherwise silently become 0/False/'None'); pass dtype=float (→ NaN) or dtype=object (→ None);
  • the unit is a whole-array property (numpy has one dtype per array) — mixed units raise, as does mixing a dimensioned element with a dimensionless one; the unit is returned alongside the data, never baked into elements.

9.2 Writing: from_numpy / array_to_bvnr

import numpy as np
import bovnar
from bovnar import Writer

with Writer.to_mem() as w:
    bovnar.from_numpy(w, "velocity",
                      np.array([1.5, 2.5], dtype=np.float32), unit="m/s")
out = w.get_output()

# one-shot convenience
raw = bovnar.array_to_bvnr("matrix", np.arange(8).reshape(2, 2, 2))

# exact decimal/fixed/wide-binary float arrays via float_format
from decimal import Decimal
prices = np.array([Decimal("19.99"), Decimal("0.01")], dtype=object)
bovnar.array_to_bvnr("p", prices, unit="$USD")            # -> <float_dec:64,$USD>
bovnar.array_to_bvnr("a", prices, float_format=("float", 128))   # binary128
  • from_numpy requires a 1-D-or-higher array; write a 0-D scalar with the scalar Writer API instead.
  • An empty axis is written as empty brackets, which keep no length for any axis after it, so only the last axis may be zero-length: shape (2, 0) is [] / [] and reads back as (2, 0), while (0, 3) would be written as [] and read back as (0,) — it raises BovnarArgumentError instead.
  • unit may be a bovnar unit string, a Unit, a ValueUnit, or a pint Unit/Quantity (anything else raises BovnarArgumentError).
  • Units apply to numeric arrays only — a unit on a bool or string array raises BovnarArgumentError.
  • An object array of Decimal/Fraction is written as an exact decimal/fixed/wide-binary float. float_format=(family, width[, frac]) — family 'float', 'float_dec' (the default for a Decimal object array), or 'float_fix' — selects the target.
  • An object array of Python ints — what to_numpy(..., dtype=object) returns for integers wider than 64 bits — is written as integers, at the narrowest width that holds them and never under 64 (<uint:71>[…]).
  • Any other object array is ambiguous and needs float_format.
  • A bytes array (dtype kind S) is refused: decode it first (arr.astype('U')).
  • A masked array with any masked entry is rejected (it would otherwise serialise the underlying value of a masked cell); fill or unmask it first.
  • array_to_bvnr grows its write buffer like dumps() (4 MiB, doubling up to 256 MiB).

9.3 pint arrays

to_pint_array and from_pint_array bridge straight through to pint Quantities backed by ndarrays, reusing the unit translation above:

q = bovnar.to_pint_array(
    bovnar.loads(b'.a=<float:64,k~m>[1,2,3];', typed=True)['a'])
# q is a pint Quantity: magnitude ndarray [1, 2, 3], unit 'kilometer'

with Writer.to_mem() as w:
    bovnar.from_pint_array(w, "dist", q)

A datetime array has no pint unit, so to_pint_array rejects it rather than wrap it as a meaningless dimensionless quantity — use to_numpy for the datetime64 array (or dtype='int64' for the raw epoch seconds).

10. Currency helpers

The bovnar.currency submodule (exposed as bovnar.currency) provides metadata for the ISO 4217 fiat and cryptocurrency BaseUnit members. It is pure Python — no library or optional dependency required.

from bovnar import currency, BaseUnit

currency.is_fiat(BaseUnit.USD)       # True
currency.is_crypto(BaseUnit.BTC)     # True

info = currency.currency_info(BaseUnit.USD)
info.code           # 'USD'
info.numeric_code   # 840 (ISO 4217 numeric; 0 for crypto)
info.minor_unit     # 2   (decimal places: 1 major = 10^minor minor units)
info.name           # 'US Dollar'

currency.minor_unit(BaseUnit.JPY)    # 0
currency.currency_code(BaseUnit.EUR) # 'EUR'

for ci in currency.all_fiat():       # all_crypto() / all_currencies() also exist
    ...

CurrencyInfo is a frozen dataclass; currency_info, minor_unit, currency_name, currency_code, and from_code raise for non-currency bases or unknown codes.

11. Reader reference

11.1 Construction

with Reader() as r:
    ...

Reader.__init__ calls bvnr_reader_create immediately. Use as a context manager or call r.close() explicitly to release the C object.

A reader is not re-entrant. While read_mem, read_fd, read_file, read_stream or iter_mem is running, the reader's own callbacks must not call close(), start another read on it, or set_unit_policy(): each raises BovnarArgumentError("Reader is in use by its own callback"), which aborts the running parse and is re-raised from the read. Use a second Reader for a nested parse, and close the first one after its read returns.

11.2 read_mem

read_mem(data, *, on_verified, on_unverified, want_unit, on_error, mirror, **options)

Parse BVNR from a bytes, bytearray, or memoryview object. The callbacks are named parameters; every other keyword is a read option, one of the names in bovnar.READ_OPTIONS. That table is the one list every reading entry point takes its keywords from — read_*, iter_mem, loads / load, the feeds (§4.7) and the bovnar.stream readers — so an option is never reachable from one and missing from another. An unknown keyword is a TypeError, a value outside its C field (a negative one, max_string_length=70000) a BovnarArgumentError. Every option defaults to 0 / False.

Parameter Type Default Description
data bytes \| bytearray \| memoryview — Input buffer
on_verified Callable[[Event, BvnrData \| None], bool] \| None None Callback for validated events
on_unverified Callable[[Event, BvnrData \| None], bool] \| None None Callback for raw pre-validation events
on_error Callable[[BovnarParseError], None] \| None None Called for every error the reader reports, as a BovnarParseError with its code and position: under continue_on_error, each error it recovers from — reported nowhere else — and the error that ends a read, before the read raises it. The mirror. mirror= — a writable binary file object (write), a socket (sendall) or a bytearray, which is appended to — is handed every byte the reader consumes, the comments and the octet-stream payloads included, so what it holds after a read that succeeded is the input. The bytes reach it a piece at a time, each once the reader has parsed it: a buffer pulled (up to 64 KiB), a piece fed to a DocumentFeed, an octet-stream chunk. A read that fails, or a callback stops, has mirrored the input up to the byte it stopped at. An exception the object raises ends the read and is re-raised from it, unchanged. read_fd, read_file, read_stream, iter_mem and DocumentFeed (§4.7) take it too; the frame readers and the demux do not, as the C objects behind them take no mirror (their caller holds the bytes it feeds them).

from bovnar import Reader

seen = bytearray()
Reader().read_mem(b'.a = 1;  # note\n', mirror=seen)
bytes(seen)                          # → b'.a = 1;  # note\n'

The five length caps and the two nesting caps are for untrusted input: lower them to what the consumer can take. The length caps are the width of their C field (uint16_t); a key or symbol longer than 255 bytes is accepted at a higher cap, but dumps() and bovnar validate keep to the default.

11.8 read_stream

read_stream(stream, *, …) — the keyword parameters of read_mem, unchanged.

Parse a document pulled from a socket (recv_into) or a binary file object (readinto1, readinto or read, in that order of preference; readinto1 hands over what a pipe or a socket file has, instead of waiting until the reader's whole request is filled). A short read is fine, and an empty one is the end of the document. The bytes are pulled as the parse needs them, so the document is never held whole. An exception the object raises is re-raised from read_stream unchanged. A text-mode file is refused, and so is a non-blocking object with nothing to read yet: a pull cannot wait, so such a transport is fed to a DocumentFeed instead (§4.7).

Write a float from a pre-formatted string in base 10 or 16. base must be 10 or 16; any other value raises BovnarArgumentError.

12.5 Struct helpers

w.begin_struct(key)   # emit ASSIGNMENT_START + STRUCT_START, increment depth
w.end_struct()        # emit STRUCT_END, decrement depth

finish() verifies that the struct depth is zero; an unclosed struct raises BovnarWriteError(GOT_INCOMPLETE_BVNR_STREAM).

12.6 Version directive

w.write_version()                   # "#!bovnar 1.2": the spec this build implements
w.write_version(major=1, minor=1)   # or declare an older version explicitly

Emits a leading #!bovnar <major>.<minor> directive. With no arguments it names the spec version this build implements (bovnar.spec_version(), 1.2) — the same directive emit_version=True writes; pass major and minor together to declare an older one. Must be called before any value is written; calling it after output has begun raises BovnarWriteError(INVALID_ARGUMENT). Use it to self-declare the spec version a document targets (spec-1.1 constructs such as datetime literals need at least 1.1 to re-read, a profile-notation unit such as ucum:[IU] needs 1.2).

12.7 Array helpers

w.begin_array_row()   # emit ARRAY_ROW_START
w.end_array_row()     # emit ARRAY_ROW_END
w.new_array_dim()     # emit ARRAY_DIM_START (the / separator between rows)

12.8 Low-level emit

w.emit(event, *, key=None, value=None, vt=None, vu=None)

Send an arbitrary event to the C writer. key and value are encoded as UTF-8. When both vt and value are supplied the token type is inferred: _TOKEN_IS_STRING for ValueTypeFamily.UTF8, and also for a vt whose base is a radix other than 10 (uint, sint or float with vt.base not 0 or 10, whose literal must be quoted); _TOKEN_IS_NUMBER otherwise. The base field of float_fix (Q), float_dec and datetime (the epoch index) is not a radix and never makes the value a string.

12.9 Octets, embedded documents and mux streams

from bovnar import Writer, stream

w = Writer.to_mem(pretty=False)
w.write_uint("before", 1)
w.mux_begin("media")              # .media = <multiplexed octet stream>
w.mux_send(1, b"frame-1")         # one message on channel 1
w.mux_send(2, b"audio")
w.mux_end()
w.embed_document("inner", b".x = 5;")   # a document as an octet value
w.write_octets("raw", b"\x00\x01")       # any bytes-like object
w.write_uint("after", 2)
w.finish()
doc = w.get_output()
stream.mux_load(doc, key="media")       # → [(1, b'frame-1'), (2, b'audio')]
stream.parse_embedded(bovnar.loads(doc)["inner"])   # → {'x': 5}

mux_begin, mux_send and mux_end wrap bvnr_mux_begin / _send / _end: the stream is one value of the document being written, so values may come before it (read back before the first message) and after it, and a document may carry more than one. The bytes of a stream are those mux_dump writes. embed_document wraps bvnr_embed_document, embedding into the document being written rather than making a document of one key, as stream.embed_document does. A key is held to the rule of dumps() (BovnarArgumentError), that of write_octets too, a channel to the unsigned 64-bit range, and a payload or a document must be bytes-like (or a str, written as UTF-8). On a to_stream writer, call flush() after mux_send for a consumer reading live (§4.8).

12.10 Observing the output: on_event

on_event(event, data), given to any constructor (§12.1), is called with each event once it has been serialised (bvnr_write_flags_t.on_event), with what reached the output: under UnitFlags.REDUCE a rescaled value's new digits and unit, not the ones it was written with. Every event the writer serialises reaches it — those of the write_* methods, emit, the struct and array helpers, the mux and embedding calls. data is a BvnrData snapshot, as a reader callback gets (None for an event without one), which may be kept.

from bovnar import Writer, UnitFlags

seen = []
w = Writer.to_mem(pretty=False, unit_flags=UnitFlags.REDUCE,
                  on_event=lambda ev, d: seen.append((ev.name, d.raw_bytes())))
w.write_uint("d", 5, unit_str="k~m")
w.finish()
w.get_output()                       # → b'.d=<uint:64,m>5000;'
seen[0]                              # → ('ASSIGNMENT_START', b'd')
seen[-1]                             # → ('DATA', b'5000')

Returning False (any false value but None) fails the write, and the writer, with SCANNER_CALLBACK_FAILED: a veto, say of a key that must not leave the process. An exception the observer raises fails it the same way and is re-raised from the write call that ran it, unchanged; a later call raises the latched BovnarWriteError, chained to that exception. The observer runs inside the C call, so it may not write to, flush, finish or destroy its own writer (BovnarArgumentError). It costs a Python call per event.

12.11 Plain values, datetimes and type annotations

from bovnar import Event, ValueTypeFamily, Writer, make_type_spec

w = Writer.to_mem(pretty=False, emit_version=True)
w.write_plain("mode", "auto")                     # a bare symbol
w.write_datetime("t", 1750000000, epoch="tai")
u8 = make_type_spec(ValueTypeFamily.UINT, 8)
w.emit(Event.ASSIGNMENT_START, key="v")
w.write_type_annotation(u8, "m")                  # types the whole array
w.begin_array_row()
w.emit(Event.DATA, value="1", vt=u8)
w.emit(Event.DATA, value="2", vt=u8)
w.end_array_row()
w.finish()
w.get_output().split(b"\n")[1]      # → b'.mode=auto;.t=<datetime:64,tai>1750000000;.v=<uint:8,m>[1,2];'

write_plain(key, value) writes value bare, as a plain symbol (bvnr_write_plain): .mode = auto;. The C writer refuses a value that is not a symbol or is a reserved word (null, true, false, on, off, nan, inf, ninf) with TYPE_VALUE_MISMATCH, an empty one with EMPTY_IDENTIFIER and one too long with SYMBOL_TOO_LONG. A NUL or a lone surrogate in it is a BovnarArgumentError, and so is a key dumps() would refuse, both raised before anything is written.

write_datetime(key, value, *, width=64, epoch=None) writes value, signed seconds since epoch ("unix", the default, "tai", "gps", "mjd", "ntp", "galileo", "glonass", "y2000", "beidou"), as <datetime:width[,epoch]> (bvnr_write_datetime). Datetime is spec 1.1, so the document must declare it first — emit_version=True, or write_version() before any value; without that the write fails with UNSUPPORTED_SPEC_VERSION, the key already in the output and the writer in its error state. An epoch the library does not know is a BovnarArgumentError, raised before anything is written. A datetime with a sub-second fraction is written by dumps() from a Quantity (§6.4).

write_type_annotation(vt, unit=None, *, unit_source=None) writes the type annotation <family:width[,_base|,qQ|,epoch][,unit]> for the value written next (bvnr_write_type_annotation): after an assignment's key, with emit sending the value, or before an array's first row, where it types the whole array. unit is a Unit, a ValueUnit or a unit string, unit_source its spelling as in §12.3. As for the typed writers, only the parameters that say something are written: no width of 0, no base 10, no unit on a string or a datetime.

The other per-type C helpers have their counterpart above: bvnr_write_string, _null and _bool in write_string, write_null and write_bool; bvnr_write_uint, _sint, _float, _float_fix, _float_dec and their _unit forms in the methods of §12.3; bvnr_write_bvnf, _bvnf_unit, _bvnf_base, _bvnf_base_unit, bvnr_write_bvni and _bvni_unit in write_bvnf_base and write_bvni (§12.4); bvnr_write_struct_start and _end in begin_struct and end_struct (§12.5); bvnr_writer_set_unit_source in unit_source=.

File-size limits: DomDoc.parse_fd and DomDoc.parse_file apply an internal ceiling of BVN_DOM_FD_MAX_BYTES (256 MiB, bovnar.dom.DOM_FD_MAX_BYTES). The DOM takes no read options. The C DOM parse functions read with a fixed set (no total cap besides the one above, the 255-level nesting, and the reader's defaults for everything else), and neither binding can pass more: read with a Reader (§11) or loads for the limits of §11.2.

Building a tree. DomDoc.create() and doc.add(key, node) are the C DOM's builder, for a tree made by hand from NewNodes (§13.5). Such a tree cannot be written out; build a document with dumps() or the Writer.

Errors: the C fd functions return NULL for an allocation failure, a read error and input over the cap alike; the binding tells them apart by errno. A read error is the matching OSError, input over the cap is BovnarParseError(FILE_TOO_LONG), and only an allocation failure is MemoryError — the one DomDoc.parse can raise, since the in-memory parse returns NULL for nothing else.

13.5 Building a tree (NewNode)

DomDoc.create() makes an empty document and NewNode the nodes to put in it: the C DOM's builder (bvn_dom_doc_create, bvn_dom_node_alloc, bvn_dom_node_from_*, bvn_dom_struct_add, bvn_dom_array_append, bvn_dom_doc_add, doc/08 §4.5). It is there for code that consumes a DOM, a test fixture say, and it has the C builder's limits: it makes structs, arrays, nulls and integers only, and a built tree cannot be written out, since the C library has no DOM serialiser. To produce a document, use dumps() or the Writer.

from bovnar import DomDoc, NewNode

server = NewNode.struct()
server.add("port", NewNode.integer(8080, width=16))
server.add("tls", NewNode.null())
ports = NewNode.array()
ports.append(NewNode.integer(80, width=16))
ports.append(NewNode.integer(443, width=16))
server.add("ports", ports)

doc = DomDoc.create()
doc.add("server", server)
big = doc.add("big", NewNode.integer(2**100, width=128, unit="m"))
doc["server.port"].as_u16()     # → 8080
big.unit_str                    # → "m"
doc.to_dict()                   # → {"server": {"port": 8080, "tls": None, "ports": [80, 443]}, "big": 1267650600228229401496703205376}
Constructor / method Description
DomDoc.create() An empty document; its parse_error is NONE
doc.add(key, node) Add node as a top-level entry and return it as a DomNode of doc. A parsed document takes one too
NewNode.null() / NewNode.struct() / NewNode.array() An empty node of that kind (bvn_dom_node_alloc)
NewNode.integer(value, *, width=64, signed=None, unit=None) An integer node of type sint:<width> or uint:<width>; signed=None is sint for a negative value and uint otherwise, as for write_bvni. A width of 8, 16, 32 or 64 is bvn_dom_node_from_i8 … _u64, which take no unit; a width of 65 to 32768 is bvn_dom_node_from_bigint, which takes unit (a unit string, Unit or ValueUnit). A value that does not fit the type, another width, or a unit on a narrow width raises BovnarArgumentError
node.add(key, child) Add child as a member of a struct node (bvn_dom_struct_add)
node.append(child) Append child to an array node (bvn_dom_array_append)
node.dom_type / len(node) The node's DomType; the number of members or elements

Ownership. The C attach functions take the node they are given on every path: on success the container owns it, and on failure they destroy it. A NewNode hands its node over once. After it is attached it is spent, and any further use of it (adding it again, adding to it, reading it) raises BovnarArgumentError: a node is in one tree at most, and a struct cannot be filled after it was attached, so a tree is built from its leaves up. A refused attach raises before anything is handed over and leaves the node with the caller; it is refused for a key that is not an identifier (§5.8; the C functions refuse only an empty one, but the path lookups could not reach another), for a key the struct or document already has (which the C function would refuse by destroying the node), for a spent node, for a node added to itself, and on the wrong kind of container. Only an allocation failure inside the C call is a MemoryError with the node gone. A NewNode collected before it is attached frees its subtree.

Reading it back. A built tree reads through DomDoc and DomNode like a parsed one, with two differences that come from the C builder: an integer node of up to 64 bits carries no unit, and a built array records no row shape, so its array_dims() is 0 and to_python() gives one flat list.

Not bound: bvn_dom_node_alloc of the other kinds (a float, string, symbol, reference, bool or octet-stream node it makes holds no value and cannot be given one), bvn_dom_strdup (a C allocation helper; the attach functions copy the key themselves), and bvn_dom_get_bigint (a borrowed bvn_int_t; as_int_str() and to_python() already read an integer of any width).

16. Error handling

All errors surface as subclasses of BovnarError. bovnar.error_message(code) is the library's text for an ErrorCode (bvn_error_to_string): "string_too_long" for ErrorCode.STRING_TOO_LONG.

Exception When raised
BovnarLibraryNotFound libbvnr.so could not be loaded — raised on first use of the C library, not at import bovnar; the message lists every path tried
BovnarParseError Parse error in Reader (carries code, line, column, offset, byte)
BovnarWriteError Write error in Writer (carries code, offset)
BovnarArgumentError Invalid argument passed to a helper (e.g. bad unit string, closed reader/writer)
TypeError An unknown keyword where read options are taken (max_string_lenght=)
OSError DomDoc.parse_fd / parse_file could not read the input (the errno subclass: IsADirectoryError, …); an over-cap input is BovnarParseError(FILE_TOO_LONG) instead
MemoryError The C library could not allocate (a reader, writer, or DOM tree)

unit_convert_factor error semantics: The C function uses the (ok, requires_affine) pair to signal four distinct outcomes:

ok requires_affine Meaning
True False Multiplicative conversion; factor is ready to use
True True Both sides are affine and share their zero (e.g. °C ↔ °Re, Réaumur), so factor alone is correct
False True Affine conversion the offsets do not cancel (e.g. °C ↔ K). factor is 0.0 — not a usable multiplier
False False Units are dimensionally incompatible → BovnarArgumentError

unit_convert_factor raises BovnarArgumentError only when both ok=False and requires_affine=False; the result carries the other three as c.ok and c.requires_affine, so check c.ok before multiplying by factor (ok is a field with a default of True, so UnitConversion(f, affine) built by hand still works). When it is False, call convert_value, which handles the two-step affine path, or call unit_to_si_factor on both units and convert by hand. The Unit method convert_factor() returns the bare number and therefore raises for the 0.0 row instead of returning it.

Callbacks returning False: When an on_verified or on_unverified callback returns False, the C parser stops and bvnr_read returns failure. The Python layer then calls _raise_error() and raises BovnarParseError with whatever error code the reader recorded. BovnarCallbackAbort is defined in exceptions.py but is not raised by the current implementation.

Callbacks raising exceptions: If the callback itself raises a Python exception, that exception is captured, the C callback returns False to stop the parse, and the original exception is re-raised from read_mem / read_fd after the C call returns.

BVN_UNIT_ASCII_EXP 1 << 1 Use ^N ASCII exponent notation instead of Unicode superscripts
BVN_NUM_CANONICAL 1 << 2 Write a float that BVN_UNIT_REDUCE rescaled in float shape (5000.0, not 5000), and every annotation in one form (width written out, default _10 and no_unit left out)

They are set from Python with the unit_flags= keyword of Writer.to_mem / to_fd / to_file / to_stream, as UnitFlags values; emit_version= sets the struct's emit_version field. max_struct_nesting= and max_array_nesting= set the struct's two nesting fields (0 becomes 255, 1–255 is a lower cap), and on_event= sets its on_event observer (§12.10).

The writer respects the unit_flags stored inside the C writer object when serialising unit annotations. _emit_annotation retrieves the live flags via bvnr_writer_unit_flags(w) and passes them to bvn_unit_to_string_ex.

17.3 write_string behaviour

Writer.write_string emits a bare quoted string with no type annotation, matching bvnr_write_string in the C library:

.host = "localhost";

To write a string with an explicit <utf8> annotation, use the low-level emit API with Event.TYPE_ANNOTATION_START / TYPE_ANNOTATION_END events before the Event.DATA event.

17.4 _resolve_unit default

When no unit arguments are supplied to write_uint, write_sint, write_float, etc., the unit resolves to BVN_UNIT_NONE (zero components), matching the C convenience helpers. No unit annotation is emitted in this case. Passing unit_si_base or unit_iec_base produces a unit with one component; the no_unit keyword is only produced when the caller explicitly constructs a dimensionless ValueUnit with BaseUnit.NONE.

17.5 Signals inside a callback

Where C calls back into Python — the event callbacks of Reader and its on_error handler, mux_load's per-message callback, load_documents, a parsing FrameFeed, the writer's on_event observer, a reader's mirror= sink, the sources and sinks of sockets and file objects — every exception the callback raises is kept, the callback answers false so that C stops, and the exception is re-raised once the C call has returned. (on_error answers nothing, so its exception stops the read at the next event callback, or waits for the read to end, §11.2.) One window is beyond the binding's reach: an exception raised by a signal handler (KeyboardInterrupt from Ctrl-C) at the very entry of a callback, before its body runs. ctypes reports it as "Exception ignored" and the call goes on as if the callback had succeeded, so the interrupt is lost and the callback's work for that event (a message, a pushed buffer) is missing. Where an interrupt must stop the work reliably, use the pull-style feeds (DemuxFeed, an unparsed FrameFeed), which make no Python callback per item, or have the signal handler set a flag the loop checks.

The plain name CUP is the US-cup volume unit (enum value 100080); since Python enum member names must be unique, the currency at value 900033 takes the suffixed name. This affects the Python member name only — the .bvnr wire token is still the bare uppercase CUP, and case stays load-bearing (cup = volume, CUP = currency).

19. Spec 1.1 additions

These bindings target the Bovnar spec 1.2; spec 1.0 remains the frozen baseline, and the package's own version (2.0.2) is a separate number (bovnar.version() against bovnar.spec_version()). Spec 1.2's one addition, the unit-profile notation, is covered in §5.1: it is gated on a #!bovnar 1.2 directive, which dumps() prepends when a kept spelling or a profile-only unit needs it. The 1.1 features (all gated on a #!bovnar 1.1 directive — an unversioned document is treated as 1.0) are exposed as:

  • Version: bovnar.version() (library version string), bovnar.version_number() (the same as one int, `major * 10000 + minor * 100
  • patch: 20100 for 2.1.0),bovnar.spec_version()→(major, minor)of the highest spec understood, andbovnar.peek_version(data)→ the(major, minor)a document declares, orNone.Reader.declared_versiongives the same after a read; every reading entry point (read_*,loads, the feeds and stream readers) acceptsstrict_version=Trueto reject a too-new version (ErrorCode.UNSUPPORTED_SPEC_VERSION`).
  • Richer escapes: \u{…} and \xHH in string literals are decoded by the C reader, so loads returns the resulting text transparently. A surrogate / out-of-range \u is ErrorCode.INVALID_CODEPOINT.
  • Datetime family: loads decodes a <datetime:width,epoch> value to a plain int (signed epoch seconds). With typed=True it is a Quantity whose .epoch_name ("unix", "tai", …) and .epoch_mjd recover the epoch, and .to_civil() its UTC date and time (§6.5); bovnar.datetime_epoch_index(name) goes the other way, to the index a datetime ValueTypeSpec holds in base (make_type_spec(ValueTypeFamily.DATETIME, 64, bovnar.datetime_epoch_index("gps"))), None for an unknown name. dumps() emits the <datetime:…> annotation and prepends #!bovnar 1.1 automatically when the object contains a datetime. With typed=True the sub-second fraction of an ISO-8601 literal (spec 1.1) is preserved on the Quantity and re-emitted, so a loads(typed=True)→dumps() round-trip is lossless (…T12:00:00.5Z survives verbatim). The plain (non-typed) value is only the whole-second int carrier, so a non-typed loads→dumps drops the fraction; to read it explicitly use the DOM tier (DomNode.datetime_fraction) or the streaming reader (bvnr_data_t.frac_data via a callback). ValueTypeFamily.DATETIME is the family enum member.
  • Reference array indexing: &.matrix[0][1] paths are stored verbatim and resolved by DomDoc.lookup("matrix[0][1]") at the DOM layer.

ErrorCode adds INVALID_SPEC_VERSION (42), UNSUPPORTED_SPEC_VERSION (43), INVALID_CODEPOINT (44), INVALID_DATETIME_LITERAL (45), and DATETIME_LITERAL_UNSUPPORTED_EPOCH (46).
